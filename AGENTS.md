# FounderAgent — Agent System

## Overview
FounderAgent is not just a chatbot. It is an autonomous finance intelligence agent that:
- Monitors financial data continuously
- Detects anomalies, duplicates, and opportunities
- Executes tasks on behalf of the user
- Generates recommendations with impact/effort scoring
- Maintains a complete audit trail

## Agent Task Types

| Task Type | Description |
|-----------|-------------|
| `find_cheaper_alternatives` | Research lower-cost alternatives to current tools |
| `detect_duplicate_subscriptions` | Find overlapping or duplicate SaaS tools |
| `flag_wasteful_spending` | Identify unnecessary or excessive expenses |
| `forecast_runway` | Project cash runway under different scenarios |
| `identify_revenue_growth` | Find opportunities to increase revenue |
| `create_cost_reduction_plan` | Generate a structured cost-saving plan |
| `generate_investor_summary` | Create board-ready financial summaries |
| `review_renewals` | Alert on upcoming subscription renewals |
| `identify_unusual_transactions` | Flag anomalous spending patterns |
| `suggest_renegotiations` | Recommend vendor contracts to renegotiate |
| `categorise_transactions` | Auto-categorise uncategorised transactions |
| `generate_report` | Generate a specific financial report |

## Task Lifecycle
```
pending → queued → running → completed/failed/cancelled
```

## Database Schema

### `agent_tasks`
Stores tasks requested by users or triggered by the system.

### `agent_recommendations`
Stores actionable recommendations generated by tasks.
- `potential_savings`: Estimated annual savings in USD
- `impact_score`: 0-100, how much value this creates
- `effort_score`: 0-100, how hard it is to implement
- `status`: new → viewed → accepted → implemented / dismissed

### `agent_activity_logs`
Audit trail of everything the agent does.

## Integration Points
- **Sidebar**: Quick task creation, agent status indicator
- **AI Drawer**: Task history, suggested actions, conversation
- **Agent Tasks Page**: Full task management UI
- **Dashboard**: Recommendation cards, alert badges
- **Subscriptions**: Flagged subscriptions from agent detection
- **Alerts**: All agent-generated alerts

## Future Enhancements
- [ ] Scheduled recurring tasks (weekly scans, monthly reports)
- [ ] Email/Slack notifications for critical findings
- [ ] One-click implementation of recommendations
- [ ] Agent confidence scoring
- [ ] Multi-step agent workflows

## Enterprise Agent Operations

This project operates with three dedicated agent roles. Every code change must pass through these agents.

### 1. Bug Fixing Agent
**File:** `.kimi/bug-fixing-agent.md`

- Reproduces every bug before fixing
- Makes minimal surgical changes
- Validates build passes after fix
- Checks for common anti-patterns (async client components, secret leaks, invalid UUIDs)

### 2. Tester / Validation Agent
**File:** `.kimi/tester-agent.md`

- Runs `npm run build` after every change
- Audits security (service role key isolation, RLS policies)
- Validates architecture (server vs client component boundaries)
- Verifies data integrity and auth flows
- Never approves code with build failures

### 3. UI / UX Testing Agent
**File:** `.kimi/ui-agent.md`

- Tests through three personas: Founder, CFO, Engineer
- Validates data consistency across pages (Dashboard ↔ Subscriptions ↔ Transactions)
- Tests empty states, edge cases, mobile responsiveness
- Ensures no placeholder text or hardcoded demo values visible to users

### Agent Workflow
```
Code Change → Bug Fixing Agent → Tester Agent → UI Agent → Approved
                ↓                      ↓              ↓
            Fix & Build           Validate       User Stories
```

**Rule:** No change is complete until all three agents sign off.
